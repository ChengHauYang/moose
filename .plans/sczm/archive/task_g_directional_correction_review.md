# Task G design review

The standard primary/neighbor stress and tangent pipeline is a sound direction: it removes the isotropic constitutive assumption from the SCZM kernel and reuses existing material storage. Revise the indexing and material-creation contracts before treating the plan as implementation-ready. The current pseudocode would retrieve the wrong side's stress and mishandle broadcast outputs.

Reviewed against working-tree baseline `4e37469f72` on 2026-10-14 using CodeGraph and source inspection. This is a design review of `task_g_directional_correction.md`, not a review of an implementation diff. No builds or MOOSE executables were run. Applicable repository guidance is the root `AGENTS.md` and the supplied MOOSE formatting instructions.

## Required design corrections

1. **[P1] Remove the second neighbor traversal from the neighbor batch mapping.** Plan lines 70-75 and 186 assume that `kokkosElementSideID(t)` identifies the primary side for a neighbor material. In `framework/src/kokkos/materials/KokkosMaterialBase.K:126`, the neighbor material's side list is already populated with `{neighbor_eid, neighbor_side}`. `NeighborCompute` constructs its datum on that side (`framework/include/kokkos/materials/KokkosMaterial.h:255`). Traversing `elem->neighbor_ptr(side)` again therefore returns the primary side. For an oriented interface A -> B, the proposed lookup writes A's output into B's neighbor property storage. Look up the batch for the current material datum's element/side; retain counterpart lookup only when starting from an explicitly primary-oriented face record. Verify this with different prescribed stresses on A and B.

2. **[P1] Define a real, consistent key for each device lookup table.** Plan lines 58-60 size arrays by restricted dispatch counts, populate side entries by thread index, then read them using `datum.sidePropertyIdx()` at lines 104-106. That method does not exist. Existing `Datum::propertyIdx()` and `qpOffset()` describe property storage, and those addresses are not the material's restricted dispatch index (`framework/include/kokkos/base/KokkosDatum.h:538`). Similarly, `datum.elemID()` is a mesh contiguous ID, so an element table sized by a block-restricted `numKokkosElements()` can be too small. Specify the key, extent, conversion from contiguous IDs to libMesh elements, and ghost coverage together. Reuse the assembly's addressing where possible, but include its subdomain context; do not treat a subdomain-local property address as a globally unique thread index. Use a block-restricted case whose contiguous IDs do not start at zero as a regression. Preserve the existing lazy mapping rebuild after the executor produces its batch indices; `meshChanged()` should invalidate the map rather than assume the new indices already exist (`framework/src/kokkos/materials/NEML2ToKokkosMaterialProperty.K:119`, `:207`).

3. **[P1] Translate host neighbor batch ordering into the neighbor's natural Kokkos QP ordering.** Plan lines 110 and 132 assume that `base + neighbor_qp` selects the corresponding NEML2 output. The host gatherer appends neighbor values using the primary interface loop's `qp` (`framework/src/neml2/userobjects/MOOSEQuantityToNEML2.C:223`). Kokkos independently evaluates the neighbor side and maps primary QPs to its natural QPs (`framework/include/kokkos/interfacekernels/KokkosInterfaceKernel.h:260`). With permutation `p(q)`, the intended relationship is `neighbor_property(B, p(q)) = output[B_batch + q]`. A base offset alone cannot express this permutation. Define a scatter into natural neighbor order, or an inverse permutation when unpacking; the consumer should apply the existing correspondence exactly once. Add a reversed-orientation face with a spatially varying stress and multiple QPs. Constant stress 100/200 detects side swaps but cannot detect a QP permutation error. Also replace the broad non-conforming claim with the actual supported contract: the current face cache requires equal QP counts and a bijective physical-point match (`framework/src/kokkos/base/KokkosInterfaceFaceCache.K:82`).

4. **[P1] Keep the entire broadcast batch index at zero.** At plan lines 101-110, `_broadcast_output` sets only `base_batch = 0`; adding `qp` still selects batch 1, 2, etc. A broadcast tensor has one tensor entry, including the zero tensor used for an undefined derivative. Use the existing behavior, `batch = _broadcast_output ? 0 : mapped_batch`, and test a broadcast rank-four derivative on a multi-QP side (`framework/include/neml2/materials/NEML2ToKokkosMaterialProperty.h:80`). Specify how the new mapping preserves the existing zero-, one-, and two-batch-dimension contracts (`framework/src/kokkos/materials/NEML2ToKokkosMaterialProperty.K:172`, `:206`), or explicitly reject unsupported side layouts with a tested diagnostic.

5. **[P1] Specify how retrievers are created without duplicating native face/neighbor copies or accessing absent batches.** Plan lines 178 and 188 leave this unresolved. `FEProblemBase::addKokkosMaterial()` already delegates to the native material helper, which creates BLOCK, FACE, and NEIGHBOR objects for a block material; boundary-restricted materials receive no automatic face/neighbor copies (`framework/src/problems/FEProblemBase.C:4219`, `:4246`). Consequently, explicitly creating primary and neighbor retrievers whenever `interface` is set could duplicate the normal copies. Conversely, only setting `boundary` in `interface_only` mode creates no neighbor writer. Describe both paths, including the material data type, unique object names, boundary selection, and block restrictions on each side. The host retriever skips sides absent from the executor's index (`framework/src/neml2/materials/NEML2ToMOOSEMaterialProperty.C:87`); the proposed unconditional lookups would error on other material boundaries or volume-only executors. Specify equivalent handling for sides outside the model's domain while retaining an error for a required but missing SCZM property. `NEML2Action` currently exposes `interface`, not a separate `boundary` parameter (`framework/src/neml2/actions/NEML2Action.C:85`); use the existing syntax or explicitly justify an API extension.

6. **[P1] Make the SCZM tensor contraction respect the declared property dimensions and device-loop rules.** Plan lines 137 and 143 loop over three stress columns, but the NEML2 Kokkos retriever declares each tensor dimension as `_mesh.dimension()` (`framework/src/kokkos/materials/NEML2ToKokkosMaterialProperty.K:92`). A 2D property therefore has no column 2. For Cartesian small strain, contract over the mesh dimension using raw counter loops in device code. If three-dimensional tensor storage is required for a coordinate-system formulation, explicitly widen and populate the property contract and audit its consumers. Do not copy `make_range(3)` into new device code: root `AGENTS.md` section 5 prohibits it, and the retriever already records a CUDA failure with this construct (`framework/include/neml2/materials/NEML2ToKokkosMaterialProperty.h:83`). The existing bulk-stress material supplies `{3,3}` tensors, so replacing that provider changes this contract.

7. **[P2] Define the tangent mathematics and supported coupling before promising arbitrary nonlinear models.** Plan lines 149-152 identify the tangent property but omit its contraction. For a strain tangent, use `test * sum_j,l nt(j) * 0.5 * [C(i,j,k,l) + C(i,j,l,k)] * grad_phi(l)`, with the stated element/neighbor signs and unshifted gradients. The host distinguishes this from a full-gradient tangent through `tangent_definition` (`modules/shifted_boundary_method/src/interfacekernels/SCZMInterfaceKernelSmallStrain.C:289`). State which definition PR 3 accepts, and keep explicit rejection of unsupported definitions and volumetric locking correction until implemented. Zero correction cross blocks follow only when each side's bulk stress depends on that side's displacement field. Models consuming an interface jump can depend on both sides; temperature-dependent stress also needs additional Jacobian couplings for a coupled solve. Narrow the promise to local small-strain constitutive models with a consistent displacement tangent, or scope the additional derivatives explicitly. Retain property retrieval only when `_shifted && _directional_correction`, so disabled-correction inputs keep working (`modules/shifted_boundary_method/src/kokkos/interfacekernels/KokkosSCZMInterfaceKernelSmallStrain.K:77`).

## Suggested implementation sequence

I suggest keeping the three stages, with the first two centered on indexing contracts rather than new dispatch code:

1. Add boundary unpacking, explicit batch-layout handling, and broadcast/missing-side coverage. Keep `Material::computeProperties()` as the dispatch entry: it already implements all three dispatches (`framework/src/kokkos/materials/KokkosMaterial.K:89`).
2. Add the two-sided creation path and QP ordering translation. Establish heterogeneous, varying-QP, interface-only, and ghost-neighbor property results before wiring SCZM to them. Separate side and neighbor arrays are optional: each native material instance has one execution context, so one context-specific lookup per instance may be simpler.
3. Change SCZM property consumption and the action's validation together. Replace tests that currently expect custom `stress`/`tangent` inputs to be rejected, migrate the existing angled and heterogeneous inputs, and define compatibility for existing users of the linear-elastic provider. Keep validation provider-independent; apply NEML2-specific interface checks when NEML2 supplies the property.

Preserve the existing owned `_staged_output` and device-to-device copy unless aliasing is a separate, justified change. Currently the unmanaged view wraps the source torch tensor and `deep_copy()` populates owned staging (`framework/src/kokkos/materials/NEML2ToKokkosMaterialProperty.K:197`). The plan's line 166 incorrectly describes staging itself as unmanaged. Device-to-device staging avoids a host round trip when output resides on the execution device; it is still a copy. No new tensor-lifetime or cross-stream ownership design is needed for this feature.

## Verification and documentation feedback

The most valuable additions to the proposed matrix are:

- A varying stress/strain field with several QPs and reversed neighbor orientation, including different materials on the two sides.
- A block-restricted model with nonzero starting contiguous element IDs, an unrelated boundary consumer, and `interface_only` output checks on both sides. Check numeric values, not just successful execution.
- Broadcast and undefined derivatives; side rank-two/rank-four Mandel unpacking, including shear; and preservation or explicit rejection of full/two-batch-dimensional paths.
- A distributed interface whose neighbor is a ghost on the assembling rank, asserting the expected numeric property. Run the same specification with serial, MPI, threads, and distributed-mesh options instead of adding an MPI-only specification, as required by `AGENTS.md` section 7. The existing interface machinery already populates ghost-neighbor metadata; do not duplicate its topology handling.
- A multistep local plasticity case with loading/unloading and a failed-step retry to check independent side histories and state rollback. Use finite differences at a smooth constitutive state for the Jacobian check. Quadratic Newton convergence is not a universal acceptance criterion at yield transitions or other nonsmooth points.

Reuse the existing 2D/3D angled, heterogeneous, no-shift, and Jacobian tests in `modules/shifted_boundary_method/test/tests/kokkos_shifted_interface/tests`. Their current comparison tolerances are `1e-8`; justify tightening to `1e-10` from measured solver/backend accuracy rather than requiring identical Exodus output. Set both `rel_err` and `abs_zero` intentionally; `abs_zero` alone is not the comparison tolerance. Add a separate serial command because the command in plan line 225 runs MPI/distributed mode only. Keep capability/device selectors so NEML2/GPU tests run in the right configurations.

The implementation test specifications need `requirement`, `design`, and `issues`, with gold files for numerical comparisons and exception tests for new input diagnostics. Update the existing retriever, NEML2 action, SCZM kernel/action, and bulk-material documentation to explain the new property contract and input migration. These are requirements for the implementation PRs; no absent test or documentation files are being reported as a defect of this planning document.
